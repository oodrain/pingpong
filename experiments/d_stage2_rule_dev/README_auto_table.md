# 自动桌面获取原型 v1 报告（提交侧几何门前置）

日期：2026-10-13 ｜ 脚本：`auto_table.py`（检测）、`auto_table_eval.py`（公开15 验收）

## 一、动机（为什么做）

当前候选栈在公开 15 上的 0.744 是**带人工标注几何**的口径；而"比赛提交现实"（测试视频无标注）只有 **0.697**——**几何门值 +0.047**（压掉 14 个误报，0° 单独 +0.10）。自动桌面就是把这个缺口补回来。

支持性测量（本迭代先行完成）：
- 通道拆解：投影 mm 通道 +0.038、图像四边形通道 +0.009；
- **角点噪声敏感性：σ≤20px 对门后 F1 基本无损、σ=40px 仍保住一半以上收益**——自动桌面只需"十几像素级"精度，不需要标注级。

## 二、方法（auto_table.py）

逐帧三通道（白线/蓝面/暗蓝，复用标注工具候选实现）产生候选四边形 → 三重先验筛选 → 固定机位时序融合：

1. **中央先验**：转播机位球桌必在画面中部（排除墙面/挡板误锁定）；
2. **球点覆盖率**：球大部分时间在桌面一带飞行（真桌候选覆盖高）——**提交管线天然可获得逐帧轨迹，先验零成本**；
3. **面积合理性**：桌面图像占比 1.2%–28%（排除巨型合并区域/细条横幅）；
4. 时序融合：多帧候选按容差 60px 聚类取中值 + 末端校验（融合结果本身需通过球点覆盖率）。

## 四、安全守卫与公开 15 系统口径（更新：v1.1）

**新增守卫**：带门发射数 < 无门发射数 ×20% 时，判"几何不可靠"→ 该视频回退纯规则（防 v000047 类"错误角点把整条视频门杀光"）。守卫在评估管线与部署管线通用（一行判断，零成本）。

**公开 15 更新结果**：

- v000047 被守卫拦截（自动角点 594px 错误 → 回退纯规则）；
- **系统口径（含守卫）= 77/37/15 = 0.748**（原 0.736）——已**追平并略超人工 GT 角点口径（0.744）**；其中略带运气成分的个案（v000010 自动门 0.750 > GT 门 0.400）如实标注。
- 结论：**单视频独立估计 + 守卫**的方案在公开 15 上已达到"可部署级"；按组投票（下节）进一步为多视频批量场景兜底。

## 五、与提交管线的关系（给 A 的说明）

- 运行时调用顺序：检波器逐帧输出 →（可用时）调用 `auto_table.estimate_table(video_path, ball_pts=逐帧球位)` → 得 corners 后传给 `event_rules.detect_events(..., table={"corners": ...})` 即可启用几何门；
- `auto_table.estimate_table` 返回 None 时按"纯规则"运行（本迭代已验证该回退的安全性与整体收益）；
- 本迭代的 v000047 类风险在**单视频独立估计**下存在；正式接入前建议先做"按组投票"版（下一迭代，约半天）。

## 七、按组投票版（v1.2，同日完成）

**动机**：提交形态是"一批视频"，同场馆固定机位的视频天然可互相投票——单条视频的错误锁定（v000047 类）会被组内多数直接覆盖。

**方法**（`auto_table_group.py`）：
1. 采集：每条视频 24 帧候选池（含球点覆盖率），缓存 `auto154_pools.json`；
2. 组共识：同来源组全部候选一起聚类，取"成员数优先 + 覆盖率门槛"最大簇的中值；
3. **客观校验**（154 专有、免费）：用训练包逐帧 table bbox 的组中值核对共识四边形（IoU≥0.3 才采用）——把错误的组共识直接拦在门外；
4. 安全守卫（部署通用）：带门发射数 < 无门 ×20% → 判几何不可靠，回退纯规则。

**结果**：

| 数据集 | 无门 | 自动门（组投票+校验+守卫） | 说明 |
|---|---|---|---|
| 公开 15（系统口径） | 0.697 | **0.748**（v1.1 单视频+守卫；公开 15 无同场馆对，组投票不适用） | 已追平/略超人工 GT 角点口径 0.744 |
| 154（候选标签 v2） | 585/459/150 = 0.658 | **585/427/150 = 0.670**（**FP −32，TP/FN 不变**） | 纯误报下降；M3.3"几何门推广 154"首个正面证据 |

- 25 个来源组中 **7 组通过了共识+bbox 双重校验**（IoU 0.41–0.94，如组 12 IoU 0.94/316 成员、组 11 IoU 0.94/299 成员）；**8 个可疑共识被 bbox 校验否决**（组 04 IoU 0.02、组 09 0.03、组 24 0.10……——校验的拦截能力被实证）；10 组未能形成共识（多为暗色/特殊场馆，通道失效，待后续补通道或跨组先验）。
- 保守设计：未过校验的组一律按纯规则运行（宁缺毋滥）；守卫在两组模式下均零触发（校验前置后已无灾难案例）。

**给提交管线的最终形态建议**：批量处理时 → 组池投票（同机位多视频）→ 若有可用先验（bbox 类）做客观校验 → 逐视频 20% 守卫兜底 → 全都不满足则纯规则。三层全部失败-open，不会比无几何更差。

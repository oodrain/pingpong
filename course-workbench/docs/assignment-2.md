# 第二次作业 · 小组开工说明

## 项目从哪里来，当前做到哪一步

第一阶段完成了《项目立项与需求文档》3.0 版，确定了目标用户、功能与质量需求、用例、验收条件和四人协作。赛题工程已有球检测、轨迹、球桌几何、触台判断和评估结果。可以继承的是识别组件，以及从 0 开始的原片帧号、原图像素坐标和结果文件等约定。

原赛题的完整分析流程面向云端双 RTX 4090。课程项目面向普通 Windows 电脑，目标是让复核人员导入本地录像，在 CPU 上分析或加载已有结果，核查原片与俯视落点，再保存或导出。当前仓库的 V0 用合成样片演示加载已有结果与人工复核。研发环境曾用 v75（25 fps）和 Rocket50（50 fps）核对跳帧与复核，仓库内置的 25 fps 和 50 fps 合成样片用于复现操作。长视频性能、真实视频定位精度和异机可用性分别验收。

全组整理成一份系统设计文档，正文包括以下内容。

|内容|写到什么程度|
|---|---|

|模块划分和接口约定|说明视频解码、轨迹、球桌、触台、复核和存储各自的职责、输入、输出、缺失值与报错。至少用同一条事件走完各模块。|

## 接口先用一条落点讲清楚

V0 已有文件接口。`run.json` 核对视频身份、尺寸和帧数，`tracks.json` 传球点，`landings.json` 传触台候选。每个候选至少有 `frame_id`、`timestamp_s`、`x` 和 `y`。样片的同一时刻在 50 fps 对应 `f90`，在 25 fps 对应 `f45`。帧号从 0 开始，坐标以原图左上为原点，向右和向下为正。

V1 需要约定原视频帧号与时间戳怎样传递，时间戳无效或者视频身份对不上时怎样反馈，四角缺失时怎样提示，重新分析后怎样关联原人工记录。CPU 初筛可沿用约 40 ms 的取样网格，碰到候选时回到附近真实源帧再定位。原视频的帧率用于读取和验收，25 Hz 是候选分析的内部设置。

## 四个人这次各交什么

|成员|负责的设计与提交内容|核验与交接|
|---|---|---|
|A 需求与工作台集成|交第一阶段承接和需求变更表、体系结构图、工作台流程或任务状态图。牵头 ADR 1「选择本地模块化单体」。维护 V0，统稿。|明确导入、分析、回看、保存与导出的边界。请 B 用自己的电脑照 README 独立启动。|
|B 数据与测试质量|交需求到设计和验收的追踪表、样片预期结果、初版验收用例。负责记录一次独立复现的设备、版本、现象和证据。收集团队协作说明。|核对两种帧率、落点跳帧、错配视频、合法零事件与失败状态。样片已能验证的内容记实际结果，后续构件记录预期结果。|
|C 视频、轨迹与球桌|交流程图，定义源帧、时间戳、轨迹、球桌四角和 A/B 方向的输入输出。牵头 ADR 2「以原片帧号与时间戳作为模块共同口径」。|给 D 一份观测样例。核对 `f90` 和 `f45` 都是 1.800 秒，验证逐帧、坐标范围和投影方向。|
|D 触台与复核|交事件结构、复核状态图和持久化设计。牵头 ADR 3「预测与人工复核分别保存」。|从 C 的观测得到候选，再把事件交给 A 的工作台。演示一条疑难或补记记录在重开后的恢复。|

追踪表可以先写一条已有需求。第一阶段 `FR04` 要求使用原片帧与原图坐标。C 在观测接口定义字段和范围，D 在事件接口与导出校验沿用，B 用 `AC03` 检查 0 帧、末帧以及非整数帧号和越界坐标。样片 `f90` 与 `f45` 可作为增加的跨帧率核对用例。

## 两项随正文一起交

- **团队协作说明。** B 收集，A 审核。按事项写实际负责人、提交物或仓库记录、参与评审的人，以及真实分歧如何解决。例如组会可比较「CPU 全片逐帧」和「初筛后局部补帧」，把讨论后的结论和依据写进对应 ADR。
- **人机协作说明。** 各成员记录本人用智能工具完成的任务，附教师和助教可访问的对话链接。每条写清工具给出的内容、自己做了哪些修改、修改理由和验证证据。A 汇总，B 检查链接与记录是否齐全。课件规定缺少修改说明和理由的条目不计分。

建议在组会上先跑同一段样片，再定帧号、时间、坐标、异常状态和文件输出。之后由 C 与 D 互查接口，B 对照验收条件走查，A 汇总为正文和两项说明。课件评分中团队协作占 15 分，人机协作占 25 分，一致性与可追踪性占 20 分。组会后及时记录真实讨论和人工修改，便于提交时核对。

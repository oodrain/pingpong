# 轻量球检测核查工具

2026-10-17。独立桌面程序，只需 Python、OpenCV、Pillow 和 Python 自带 Tk；不需要 GPU、TCN、台面模型或球检测权重。工具查看已有预测，不在界面里训练或执行检测模型。

## 给组员的最短操作

1. 下载本分支 `tools/ball_detection_review.zip`，解压到仓库之外的固定目录。也可直接使用本目录源码。
2. Windows 安装 Python 3.12，双击 `安装环境.cmd`，完成后双击 `启动核查.cmd`。
3. 点击“选择数据根目录”，选择已有数据中同时包含 `rallies_videos/` 与 `annotations/` 的目录。例如下图结构：

```text
数据根目录/
  rallies_videos/B/00/001.mp4
  rallies_videos/C/11/004.mp4
  annotations/00/001.json
  annotations/11/004.json
  ...
```

4. 点击“载入基线预测目录”，选择组内另行共享的 `ball_review_predictions/`，里面应有 `00_001.json` 等六份逐帧预测。没有加载预测时仍可查看视频和球框，界面显示“未载入”，不会把它当成模型漏检。
5. 按案例查看原图、前后帧和放大图；选择可见性、核查哪条预测与检测现象，按 S 保存。点原图只移动放大区域，不会修改球框或标注球心。
6. 把独立生成的 `local_output/reviews.json` 交回。保存按钮只保存当前帧；切换前先保存。原视频及原对象标注不会修改。

Windows 桌面已完成本轮验收。Linux/macOS 可在独立环境尝试 `python -m pip install -r requirements.txt`、`python review.py`，Python 需提供 Tk 桌面支持；这两个平台尚未单独验收。

## 看什么

- 绿色框：原对象标注的球框，仍需人工核查可见性。
- 青色圆：基线；橙色标记：新模型。实心表示达到 0.75 可信门槛，空心表示低置信或无效。
- 关闭叠加可看原图；单击视频移动放大区域。左右键逐帧，N/P 切换案例，空格按 10 帧/秒慢放，O 切换叠加，S 保存。
- 帧号从 0 开始。显示解码时间；预测文件有真实时间戳时保留其原值。不能靠修改帧号或放宽到相邻帧掩盖球检测错位。
- 已有球框不等于该帧清晰可见；无球框不等于确认没有球。完全遮挡、离场、无法判断必须分开。

当前有六段开发视频的 57 个关注帧：44 个未输出点、9 个低置信、4 个尾帧未推理。它们是待核查清单，不是 57 个已确认的模型漏检；其中视频首帧也需检查上下文。没有加入原图、球框坐标或预测坐标。`v000047 f36` 在当前缓存已有可信球点，未列为当前漏检。

六段为 `00_001 / 02_006 / 10_001 / 11_004 / 16_004 / 20_004`。这些视频已用于历史开发，只能用于诊断与开发回归。后续训练继续按原始录像来源冻结划分，不把这里的困难案例清单当成独立测试集。

## 对照新模型

新模型导出同样的原图坐标、逐帧数组，放在另一个目录中，以视频编号命名，例如 `11_004.json` 或 `11_004.jsonl`。每一解码帧都要有一条记录，缺失也保留该行：

```json
{"frame_id":0,"timestamp_s":0.0,"detected":false,"x":null,"y":null,"confidence":null,"in_image":false,"missing_reason":"no_detection"}
```

有检测时填写 `detected=true`、有限的原图像素 x/y 和 0～1 置信度。不能用触台事件列表替代球轨迹。不同帧数、错位帧号、NaN 坐标会报错。选择“载入新模型预测目录”即可同帧查看；置信度尺度不同需单独记录，不能只为过门槛临时改变阈值。

## 独立评价球检测

在本目录运行：

```bash
python evaluate.py --dataset-root /path/to/data --predictions /path/to/ball_review_predictions --output local_output/baseline.json
python evaluate.py --dataset-root /path/to/data --predictions /path/to/new_predictions --reviews local_output/reviews.json --output local_output/new.json
```

比较新旧模型时，两次必须使用相同数据、相同可见性核查文件和相同门槛；如果已经核查，应把同一 `--reviews` 同时传给基线和新模型。

评测严格同帧匹配，沿用“球点进入原球框外扩一个 512×288 热图像素”的口径，分别统计命中、无输出、低置信、误定位、尾帧未推理及分视角结果。`occluded/uncertain` 帧排除；没有球框的帧视为未知；只有人工确认 `out` 才统计该类背景误报。已标可见但缺少球框的帧仍无法评价位置，需要另行补位置标注。

未核查前的六段基线参考为：606 个有球框帧，548 个可信定位命中、1 个可信误定位、57 个缺失或低置信。这个参考不是完整检测器 F1；脚本不计算触台 F1，也不会把未标注帧当负例。

## 组内准备预测包

组长从已有缓存准备即可，不必重新跑模型：

```bash
python prepare_review_pack.py --predictions /path/to/current_inputs --output /path/to/ball_review_predictions
```

支持 `视频编号.json`、`视频编号.jsonl` 或 `视频编号/control.json` 等结构。该命令只导出六段逐帧自动预测，移除无关字段，不复制视频、标注或模型。视频及对象标注继续使用组员已有数据；预测包通过组内共享存储提供，不放 Git。当前工具不提供完整球检测训练包。

## 本阶段做了哪些修改

- **触台**：保留逐帧 TCN，加入遮挡时的可信台面保留与轨迹接触点几何复核。当前内部整段时间事件 F1 87.22%，可信窗口 89.70%；不是官方空间与时间联合成绩或独立盲测。
- **球检测**：仍使用官方原权重。保留自动局部重检；增加批处理、缓冲及 GPU 输出/传输优化。小检测头微调和其他候选流程未稳定改善最终事件结果，没有替换当前默认模型。
- **性能**：C2 几何等价优化和流水线已交付，新增 GPU 路径仍待云端验收，50 FPS 尚未证明。
- **本工具**：把球是否可见、是否出点、置信度不足与位置错误分开核查，方便组员独立优化球检测，避免把 TCN 分类问题都归给检测器。

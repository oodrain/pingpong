# 组员自制标注工具与结果格式要求

版本：v2；更新日期：2026-10-07。

适用于使用现有工具、其他工具或自行开发工具的组员。开发语言、界面和内部保存方式不限；统一的是输入数据、标注口径和最终交回格式。自制工具采用下面的v2标准，旧v1文件仍由统一校验器兼容。

统一校验器随 [标注工具 ZIP](../../tools/pingpong-annotation-local-20261007.zip) 提供。在仓库根目录执行本文命令，将 `<工具包目录>` 替换为解压得到的 `pingpong-annotation-tool` 绝对路径；校验器不需要安装图形工具依赖。

## 1. 工具最低要求

|必须具备|要求|
|---|---|
|批量导入|接入分配的视频和对应官方对象JSON；识别原video_id；找不到配对或存在歧义时提示，不能猜选|
|视频查看|播放/暂停、前后逐帧、按0基帧号跳转、放大查看；标注时准确定位原视频帧|
|触台标注|记录触台帧和可见球心，支持增加、修改、删除|
|疑难标注|记录起止帧和具体原因，不强填无法判断的触台时刻或坐标|
|保存恢复|能保存、退出后恢复；不覆盖另一成员的成果，不把已有标签套到不同输入|
|完成声明|由成员确认已完整人工检查；允许保存草稿，无触台时完成必须填写原因|
|标准导出|每个视频、成员和轮次分别导出，提供一键导出，批量任务应支持批量导出|

干扰事件、参考框/轨迹、独立复核界面可按需要实现。账号系统、任务分配系统、联网同步和模型推理不是最低要求。复核可以使用现有工具完成。

输入文件可以位于任意目录，视频和JSON也可以分放在同一任务目录的不同子目录。成员编号与任务分工由组长在工具外说明。

## 2. 统一标注口径

- **帧号**：顺序解码编号，第一帧为0；不能用播放器时间、截图序号或模型处理帧号代替。
- **坐标**：使用原图像素。左上角为(0,0)，x向右、y向下；缩放或局部放大后必须换算回原图。
- **范围**：0 ≤ frame_id < n_frames，0 ≤ x < width，0 ≤ y < height；坐标允许小数。
- **触台**：结合接触前后连续画面判断，通常至少查看前后3帧。官方球框和轨迹仅作参考。
- **疑难**：遮挡、帧间接触、球心不可见等情况保存区间和原因；不猜测精确帧号或坐标。
- **干扰**：触网、触地、击球等不写入触台文件，可单独记录。
- **输入核对**：实际解码的帧数和尺寸与对象JSON核对；不一致时停止标注并联系组长。
- **完成**：人工声明已完整检查，不强制工具显示过全部帧，不需要逐帧确认。播放过不自动算完成。

## 3. 交回的目录与文件

每段、每轮必交metadata.json、events.jsonl、uncertain.jsonl；non_table_events.jsonl可选。现有工具固定生成四个文件。

```text
交回根目录/                       # 建议命名为labels
  A/
    03_007/
      initial/
        metadata.json
        events.jsonl
        uncertain.jsonl
        non_table_events.jsonl   # 可选
  B/
    03_007/
      review/
        metadata.json
        events.jsonl
        uncertain.jsonl
        non_table_events.jsonl
```

- 成员为A/B/C/D；video_id沿用现有编号，格式为两位数字_三位数字，如03_007。
- initial表示初标，review表示另一成员的独立复核；目录与文件里的身份字段必须一致。
- 没有触台或疑难时，对应JSONL保留为空文件，不能省略必交文件，也不要写成外层数组。
- JSON/JSONL采用UTF-8、不带BOM，换行建议LF。JSONL每行一个对象，不写注释、尾逗号、NaN或Infinity。
- 每份提交的所有记录event_id必须唯一；修改同一记录时保留其event_id。
- 标准结果目录只放上述文件及可选README.md；session、缓存、视频、原始对象JSON和环境留在本地。

**以下示例仅解释格式，事件、尺寸和时间不代表实际成果。哈希为明确占位符，提交前必须计算真实值，不能直接交示例。**

## 4. 记录格式

### 4.1 触台：events.jsonl

```json
{"event_id":"03_007_A_initial_000060","video_id":"03_007","frame_id":60,"x":787.6,"y":550.4,"event_type":"table_bounce","review_state":"provisional","round":"initial","annotator":"A"}
```

event_type固定table_bounce，review_state固定provisional，表示人工候选。按frame_id升序排列，同一视频、成员、轮次的一帧最多一条触台记录；修改坐标应更新原记录。

### 4.2 疑难：uncertain.jsonl

```json
{"event_id":"03_007_A_initial_uncertain_000032_000039","video_id":"03_007","frame_start":32,"frame_end":39,"reason":"小球被遮挡，无法确定触台时刻","review_state":"uncertain","round":"initial","annotator":"A"}
```

两端都包含，满足0 ≤ frame_start ≤ frame_end < n_frames。reason必须是具体原因，状态固定uncertain；不添加frame_id、x、y。按起止帧排序，相同区间合并说明。疑难与触台在时间上重叠时保留，不自动删除。

### 4.3 干扰：non_table_events.jsonl（可选）

```json
{"event_id":"03_007_A_initial_net_000095","video_id":"03_007","frame_id":95,"x":null,"y":null,"event_type":"net_contact","reason":"连续画面可见球撞网","review_state":"provisional","round":"initial","annotator":"A"}
```

类型仅使用net_contact（触网）、floor_contact（触地）、racket_contact（击球）、other（其他）。必须有原因；坐标可以同时为null，不能只空一个。按frame_id、event_type排序，同帧同类型不重复。

## 5. 元数据：metadata.json

下面是一份未完成初标的结构示例，所有字段均应保留：

```json
{
  "schema_version": 2,
  "video_id": "03_007",
  "annotator": "A",
  "round": "initial",
  "width": 1920,
  "height": 1080,
  "n_frames": 117,
  "fps": 25.0,
  "video_sha256": "<视频文件的真实SHA256>",
  "annotation_sha256": "<官方对象JSON文件的真实SHA256>",
  "completed": false,
  "completion_basis": null,
  "checked_ranges": [[0, 60]],
  "displayed_ranges": [[0, 60]],
  "no_events_reason": "",
  "label_version": 1,
  "updated_at": "2026-10-07T15:00:00+08:00",
  "tool": "my-annotation-tool/1.0",
  "source_type": "manual",
  "review_of": null
}
```

|字段|填写规则|
|---|---|
|schema_version|整数2，不与标签版本label_version混淆|
|video_id、annotator、round|与输入视频、目录及每条记录一致|
|width、height、n_frames|实际解码得到的正整数，不照抄示例|
|fps|实际视频帧率，有限且大于0|
|video_sha256、annotation_sha256|对两个原始输入文件的字节分别计算SHA256，保存为小写64位十六进制|
|completed|草稿为false；人工确认整段检查完成为true|
|completion_basis|完成为manual_attestation，草稿为null|
|checked_ranges|人工检查声明的范围；完成时必须为[[0,n_frames-1]]，草稿只填明确检查的范围|
|displayed_ranges|工具实际显示过的帧范围，不要求完成时全覆盖；没有可靠显示记录则为null，不编造范围|
|no_events_reason|完成且events为空时必须填写原因；其他情况可为空字符串|
|label_version|首次为1；修改已交内容后递增，不变不升版本|
|updated_at|带时区的ISO 8601时间，如示例中的+08:00|
|tool|实际工具名称和版本，非空字符串|
|source_type|自行标注为manual；继承旧标签为imported，并加note说明来源|
|review_of|初标为null；复核必须填写其绑定的初标来源，见下一节|

checked_ranges和displayed_ranges的区间都包含两端，必须在帧范围内，按顺序排列并合并相邻或重叠区间。两者不可混用：人工完成声明不是程序验证过的全帧显示记录。

计算输入哈希的Python示例：

```python
import hashlib

def sha256_file(path):
    result = hashlib.sha256()
    with open(path, "rb") as stream:
        for block in iter(lambda: stream.read(1024 * 1024), b""):
            result.update(block)
    return result.hexdigest()
```

## 6. 复核要求（需要复核时适用）

复核者必须与初标者不同，依据同一视频和对象JSON。初标须已完成；独立判断前隐藏初标人工记录，完成后再对照，复核不覆盖初标。

review的metadata.review_of必须包含初标者annotator、label_version，以及metadata_sha256、events_sha256、uncertain_sha256。不要手填或猜测，可在项目根目录运行：

```powershell
python "<工具包目录>/development/annotation/submission.py" reference labels/A/03_007/initial
```

将输出对象原样写入review_of。来源文件哈希按CRLF转LF后的字节计算；输入视频和JSON哈希则按原始字节计算，不做换行转换。

汇总校验时应同时包含来源初标包。初标后来修改，旧复核保留但标记为过期，重做复核应绑定新版本。当前所有触台记录仍为provisional，不因为“完成”或“一致”自动变成可靠训练标签。

## 7. 首段验收与交回

先完成一段测试，经组长核对后再批量推进：

- [ ] 视频ID、首尾帧、实际帧数和尺寸正确。
- [ ] 原图与缩放/放大视图点同一位置，坐标恢复误差不超过1像素。
- [ ] 增加、修改、删除记录可用，保存后重启记录一致。
- [ ] 帧号、坐标、类型、排序、唯一ID和目录身份符合标准。
- [ ] 真正计算两个输入哈希；无触台有原因，疑难有具体说明。
- [ ] 草稿与完成分开；未把播放进度伪装成人工检查。
- [ ] 保留旧结果，重新交付修改版时递增label_version。
- [ ] 运行统一校验通过，再人工抽查内容。

校验器仅需Python 3.10及以上和标准库，不要求安装OpenCV。在项目根目录执行：

```powershell
python "<工具包目录>/development/annotation/submission.py" validate labels
```

把labels替换为自己的交回根目录；该目录下一层应是A/B/C/D，不能直接把成员目录A作为根目录。不要选择同时放有视频、代码等其他材料的项目根目录。

汇总初标与复核后检查过期来源：

```powershell
python "<工具包目录>/development/annotation/submission.py" validate labels --require-current-reviews
```

默认不校验固定任务分配；需要核对分工或本地输入哈希时，按[完整提交标准](标注文件与GitHub提交标准.md)显式提供--tasks及相关参数。

**交回完整的成员/视频/轮次目录，空JSONL也保留。格式通过不代表人工判断正确，仍需抽查或复核。** 这些文件用于团队人工标注交换，不直接作为比赛预测提交。

现有工具的安装和操作见[组员上手说明](标注工具_组员上手说明.md)。

# 数据与实验协作规范

统一依据：`data/splits/team_split_v1.json`；标注快照：`labels/local_development_20261022/`。每个00～24目录由用户确认为独立原始录像；公开样例与这些来源的关系尚未完全核实。

| 数据 | 数量 | 当前用途 |
|---|---:|---|
| 开发池 | 123段、20来源 | 可用于训练、来源分组的内层选型和开发验证；不是全部固定作为训练集 |
| 内部保留 | 31段、来源09/12/15/17/24 | 当前禁止训练、早停、检查点选择、阈值及版本选型 |
| 公开样例 | 15段 | 工程验收和开发回归，近期不参与选型 |

开发池包含42段精确核查视频及81段补充正例视频。42段可信范围中166次触台，20段完整核查视频中112次是其子集。81段及其他精确范围外的缺标保持未知。快照另整理625条去重确认正例用于原命中保护，不能与112/166相加或用它计算全视频精确率。

每次实验必须记录：代码提交、模型哈希、输入与标签版本、按视频及来源列出的训练/早停/检查点选择/候选比较清单、预定预算、评分范围、原命中丢失情况。保留原模型和同条件对照；选型先限于预定拟合来源内部分组验证，最终验收范围与预算须先冻结。看过的保留或公开错误不能继续用来反复追加试验。

来源隔离是整个原始录像隔离，不能把同一录像的不同短片随机分进训练和验证。内层拟合、校准、留出来源名单随实验保存；不根据本轮结果换划分。

每次验收同时做两件事：在精确范围计算事件评分；用全部已有确认正例检查原方案命中过的事件是否丢失。必须复核任何损失，不能凭局部F1上升直接采用。工程兼容、开发回归、来源留出与真正独立盲测分别描述。

历史使用情况逐次如实记录。参与训练或版本选择的数据仍可用于开发回归，不再是该版本的未接触测试。仅被整理、导出或核对标注不能一概等同于参与训练，也不据此推断已过拟合。

用户提供的C说明：公开样例中某视频（报告编号v00085，对应命名待C核对）以73/95/139/177帧为中心的4组三帧曾作局部背景监督。此处记录的是团队回复，尚未据实际训练日志核验；不能扩写成全部15段事件标签参与训练。C完整训练、早停、144组选型来源仍需补齐。

补标前查询已有初标、复标、裁决与此快照。新增标注保留版本、视频哈希、完成状态、疑难和核查范围，不能直接改历史标签。草稿可以共享讨论，但不能进入已完成GT。

团队成员拉取统一仓库后，可用标准库运行：

```bash
python development/evaluation/team_data.py
python -m unittest discover -s development/evaluation -p test_team_data.py
```

`team_data.py`是离线评估工具，标签不进入最终只输入视频的推理流程。外部视频、已有官方对象JSON及受限权重仍按许可渠道获取，不将整套本地输入和缓存提交Git。

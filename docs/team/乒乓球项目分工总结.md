# 乒乓球项目分工总结

更新：2026年10月7日

本总结按步骤整理最终分工，当前已确认第一步：项目大体流程与角色分配。

## 第一步：项目大体流程与角色分配

### 1. 项目目标与总体思路

本项目从乒乓球视频中识别球触台的时刻，输出**实际帧号和原图像素坐标**。

先沿用官方球检测模型，通过人工标注和轨迹分析定位问题，重点改进触台判断规则；如果检测持续漏球或定位不准，再推进检测改进。

### 2. 项目大体流程

**准备数据与统一标准 → 人工初标及交叉复核 → 球检测与轨迹提取 → 触台判断 → 评估与改进 → 整合测试与提交。**

|环节|主要工作|牵头与配合|
|---|---|---|
|数据准备|整理视频、已有对象标注和样本来源，统一标注口径|B牵头，全员配合|
|人工标注|记录触台事件、触网/触地等干扰及疑难，完成独立交叉复核|全员承担，B组织汇总|
|球检测|运行官方模型，导出逐帧球位、置信度和缺失记录，核对帧号与坐标|C负责，A支持环境|
|触台判断|复现旧规则，根据轨迹分析误判，开展规则改进|D负责，B、C配合|
|评估改进|对照人工标签，分析误报和漏报，比较新旧方案|B负责评估，C、D按原因改进|
|整合提交|接入完整推理流程，检查精度、速度和输出格式，整理提交版本|A负责，全员验收|

**标注与算法开发并行推进。**先用少量完成复核的视频跑通流程，再逐步扩大验证，不等待全部154段标完才开始算法工作。已有对象框用于分析球的位置，触台事件答案由人工补标提供。

### 3. 四人角色分配

|成员|角色|主要责任|主要交付|
|---|---|---|---|
|A|协调与整合|统筹进度、运行环境和GPU；保存基线；整合检测与规则；组织测试和提交|可运行程序、运行说明、测试记录与提交版本|
|B|数据与评估|整理数据与标注标准；组织复核和疑难讨论；汇总标签；评估及可视化|复核标签、进度记录、错误画面和结果对照|
|C|球检测|导出真实模型轨迹；核对帧号和坐标；分析漏检、跳点及定位偏差|检测轨迹、检测问题样例和模块说明|
|D|触台判断|复现旧规则；分析事件误判；改进规则并开展对照；交接事件模块|规则代码、配置、新旧对照和使用说明|

标注由四人共同承担，当前分配为：

|成员|初标任务|交叉复核任务|
|---|---:|---|
|A|39段|复核D的38段|
|B|39段|复核A的39段|
|C|38段|复核B的39段|
|D|38段|复核C的38段|

复核者先独立完整观看，再对照初标；分歧由B汇总，全员讨论。标注工具可以自选，交回文件遵守[统一提交标准](../guides/标注文件与GitHub提交标准.md)，初标与复核分别保留。具体视频分配以[任务清单](../../data/manifests/tasks.json)为准。

### 4. 协作与验收原则

- **C交轨迹给D，D交事件模块给A，B提供标签和评估反馈，A完成整合。**帧号与坐标由C/A统一转换，避免重复修正。
- 首批成果须能由另一位组员运行，真实轨迹与旧规则回放一致，人工标签经过交叉复核，并完成一次有依据的新旧对照。
- 后续在更多样本和三个视角上验证，比较平均F1及官方端到端速度，目标至少50 FPS；没有可信收益时保留基线。
- 本轮沿用已确认的A/B/C/D主责和现有标注分配。具体工期、样本划分及每人详细任务留待后续步骤确定。
